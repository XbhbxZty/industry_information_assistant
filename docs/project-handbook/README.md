- 一百三十余处版本化源码片段（准确数量见页面顶部和生成输出），保留文件路径、原行号和整文件 SHA-256。源码在文档内部，不依赖本机编辑器协议。
- 本地标题/关键词/源码路径搜索、折叠内容自动展开、文内返回阅读位置、明暗主题、复制源码定位。搜索不是全文检索；全文可使用浏览器查找。

## 代码依据与事实边界

代码基线：`f5f8d17b4d257c2c698466962b001d0f6996e2ae`。

`build.mjs` 只从明确列举的、该提交下的仓库文件读取片段，不读取工作树新改动、环境文件、数据库或企业材料。每个引用锚点必须唯一，否则生成失败；不会静默选取同名的第一个结果。

正文区分当前源码、既有验收记录与后续能力。后端 102 项、前端 8 项以及 24 项已有类型诊断均来自基线阶段的历史记录，不是本次重新运行业务测试。来源 JSON 为合成示例，不能证明真实企业事实已核实。页面的版本切换只改变说明，不调用任何业务接口。

这是尽调主线学习手册，不是全仓库逐函数 API 全集。历史聊天、新闻、记忆等外围功能在业务地图定位；正文不把未接线组件写成已经工作的用户流程。

档案材料不自动进入个人知识库或研究快照；当前档案关键词检索、个人知识库链路、独立离线案例检索组件与未来组织级 RAG 分开展示。保理场景项目前独立统计，不参与核心二十项完整度、评级与闸门；探索性 LLM 发现也不能直接修改裁决。普通读取的兼容空结果与复核工作台的严格错误处理分别说明。

## 维护与验证

在项目根目录执行（Node.js 22 验证通过，不需安装新包）：

```shell
node docs/project-handbook/build.mjs
node docs/project-handbook/verify.mjs
```

- 编辑 `handbook.template.html`（外壳、原样章、术语和交互）或 `chapters/*.html`（其他章节），然后生成 `index.html`；不要直接维护生成文件。
- 每组章节对应一个 `.refs.json`；条目格式为 `[源码ID, 标题, 仓库路径, 唯一上下文锚点, 片段行数, 可选前置行数]`。生成器合并这些引用与原样章引用，不允许重复 ID 或歧义锚点。新增章节组须同步生成器和验证器的显式文件清单。
- `build.mjs --check` 检查可复现性，只读，不覆盖文件。
- 更新源码基线时，必须同步复核讲解、字段含义、引用范围和测试依据；不自动跟随 HEAD。
- 十二组验证包括文内链接、十二章正文和源码清单完整性、旧版所有 ID 保留、显式标签嵌套、SVG 几何数值、离线依赖约束、脚本语法与元素引用、搜索/版本示意逻辑、JSON 解析和生成一致性。旧版链接契约以已提交的 `7b4c66e` 为依据，因此运行验证需要包含该提交的 Git 历史；阅读成品不需要 Git。
- 未进行浏览器视觉和真实 DOM 交互验收；静态检查、逻辑测试不能证明排版或浏览器行为完全正确。没有启动业务服务、迁移数据库或重新运行业务验收。

建议第一次按章节顺序阅读，第二次从“某个值为什么变成这个结论”逆向沿链接追到来源、证据和代码。仍有不清楚的子过程，可在对应章节原位加深；文档问题与解决办法记录在 `../DEVELOPMENT_TRACE.md`。
