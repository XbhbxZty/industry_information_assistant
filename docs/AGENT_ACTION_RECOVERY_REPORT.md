# 行动选择与错误恢复：第一部分修复

日期：2026-09-28。执行顺序以 [执行约定与错误记录](AGENT_EXECUTION_AGREEMENTS.md) 为准。

## 范围与实现

只修改调查循环的行动可用性和失败反馈；不增加业务模块，不改变工作记忆投影、计划细化政策、Writer/Critic、分析来源、评分或额度规则。

- 根据当前状态提供轻量行动候选：已有计划不再开放重复建计划；未建立必需计划时只推荐建计划。
- 阅读候选基于实际分页回执和片段覆盖，区分 `read` 与全文读完；支持 `next_offset=0`、稀疏片段序号以及跨片段后的新来源 ID，不默认推荐缓存重读。
- 候选不等于权限白名单。必要重访仍可执行但不算进展；连续无进展不再一概禁用搜索，新检索仍由模型决定。真实性、来源授权和引用校验继续由工具负责。
- 引用错误返回稳定错误码、具体字段路径和有限修复信息。未读来源给阅读入口；无效引用只给已授权且确实读过的引用选项；无效底稿只列实际底稿 ID。模型负责选择、补读、计算和重试，不自动删引用、替换底稿或标记完成。
- 未知/撤权来源不回显旧目录、标题或原文。未完成校验不写入计算或答复，不改变字段核实与风险评级。
- 没有新进展时，同参数的确定性验证失败不重复执行工具，保留原错误和修复信息；明确记为 `retry_suppressed/executed=false`。发生真实进展后可重试原参数；普通返回失败及未知引用解析异常保留一次重试机会。
- 仍沿用累计 24 步/420 秒、连续 3 次无进展停止、取消传播及部分交付约束，不用扩大预算掩盖问题。

## 验证

累计新增 56 项离线回归（引用/底稿/语法错误 42 项，行动选择与恢复 14 项）。最终扩展组合 **469 项通过**（78.35 秒，28 项既存依赖警告），包括调查、报告质量/复核、证据、交付与风险边界。中断恢复后含工具契约的核心组合亦有 221 项通过。以上包含关系不累加，也不是全仓库测试。

交叉审查发现并修正：`citation_resolution_failed` 代表未知解析异常，不能与确定性校验失败同样在第一次失败后就抑制；现在显式区分，并对返回错误、抛出异常及第二次成功分别回归。

扩展测试曾出现 3 个旧断言失败：它们要求未知来源 ID 返回整份旧来源目录。本轮为防止撤权资料泄露改用授权目录读取入口，测试随契约更新后重跑通过。另两处旧恢复断言也更新为“停止推荐缓存，但保留必要重访权限”，不是放松无进展判断。

离线通过不证明最终报告达到原 T01/QL 内容目标；既有两轮失败归档不改写。

## 第一次真实模型验证：仍失败

`ACTION-recovery-T01-001` 使用提交 `42a1f87`、原 qwen-plus、原五份 T01 材料、原查询和 24 步/420 秒预算，仅运行 Investigator，不运行 HTTP/UI、Writer 或 Critic。真实 owner、同一测试数据库与五份向量正文均已核对；不上传 ORACLE，不写数据库或提交审批。运行入口支持新目录归档，拒绝覆盖旧结果。

实际 8 步、98.97 秒后 `stalled`，读了 4/5 份资料，三个问题均 `open`，有效底稿和答复均为零。没有重建计划或缓存重读，但三次计算都使用不支持的 `abs(...)`；只改标签和限制，没有修复表达式。引文恢复没有被触发，不能宣称这一能力已得到实测验证。

还观察到模型在未读时编造 `-1240`、`+980` 等计划前提，随后反说这些错误数值来自用户，并漏掉多个已有材料支持的核心分析。这属于未解决的计划/记忆与内容问题，不是用户输入错误；本轮不以此越过已确认的阶段边界。详见 [独立评估](../backend/eval/agent_e2e_pack/runs/ACTION-recovery-T01-001/evaluation.md)；原始结果保留不改写。

### 根据实测补充的同范围修复

为不支持的表达式/语法错误增加 `calculation_expression_invalid`、`field_path=expression` 和具体修复说明：必须改表达式本身，保留引文数值符号；正负处理及百分比运算由模型明确选择，程序不重写。四则 AST 白名单、事实常量限制、引文真实性与原子性均不放宽；计算可执行不代表其归因含义正确。新增 5 项测试，相关组合 147 项、最终扩展组合 469 项通过；第二次真实结果另行记录。

本轮核心提交：`6757b8c` 记录优先级错误；`3ba8bbe` 行动候选和引用/底稿错误恢复；`42a1f87` 可审计的原 T01 测试入口；`e999da1` 补齐计算语法反馈并保存首次真实失败。

## 第二次真实模型验证：局部恢复成功，内容仍未通过

`ACTION-recovery-T01-002` 使用 `e999da1`（加入计算语法反馈），与 001 同模型、同问题、同材料和同预算。调查 19 步、275.95 秒（整个程序 281.375 秒），最终 `completed/partial=false`；实际读完 5/5 份资料，另有两次缓存重读均如实记为无进展，生成 4 份底稿、四个问题均标记为 `answered`。

观察到一个真实恢复样本：第 3 步答复因缺少计算底稿被 `calculation_required` 拒绝，返回具体字段与修复信息；第 4 步调用 `calculate` 产生 c1，第 5 步重新答复 p1 成功。证明本次模型实际使用了补算路径，不代表恢复已具统计稳定性。

本次没有 `abs`、无效引文或重复建计划失败，**不能宣称这些错误的真实恢复已验证**；计算语法恢复目前有离线回归证据。没有修改旧失败或反复更改输入求通过。

内容仍不合格，不能把 `completed/answered` 解释为结论正确：

- p1 正确披露缺上期调节项，最终概述却仍认定应收增加是同比转负主因，前后矛盾。
- p4 把应为 360 的金额写成 460，把约 54.54% 称为“超六成”，还无依据将一年以内应收归作逾期。
- c4 计算 `280/870=0.321839…` 却将单位标为 `%`，与正文 `32.18%` 不一致；算术正确不等于单位/分析正确。
- 根据短账龄回收比例低便断言周转恶化、回款不可持续，超出材料能支持的范围；长账龄剩余 590、账龄占比 10%→30% 等仍未完整交付。

原始结果与独立评价在 [002 归档](../backend/eval/agent_e2e_pack/runs/ACTION-recovery-T01-002/evaluation.md)。本轮没有运行 Writer/Critic、HTTP 或浏览器，也未重启前后端；不能宣称完整报告或复核闭环通过。

归档复核：两轮 JSON 均可解析，输入问题、截止日、模型和材料哈希一致，凭据模式扫描未发现匹配；001 原始文件哈希未改变。002 的 30 个正式答复/底稿引文绑定均与实际已读原文及 quote_id 一致，这只证明定位，不抵消上列内容错误，也不代表安全专项验收。
