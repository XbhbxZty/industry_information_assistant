# 基线实测：V1 (ReAct 单体) vs V2 (多智能体)

> 实测时间：2026-08-09 ｜ 在删除 V1 链路（Stage 0.4）之前留存的一手对比数据
>
> 用途：回答"为什么需要多智能体架构"，以及为反幻觉工程（`DESIGN_CORE_MECHANISMS.md`）提供实证依据

## 实验设置

| 项 | 值 |
|---|---|
| 问题 | 供应链金融行业的市场现状、主要风险与监管趋势 |
| 端点 | `GET /research/stream?version=v1\|v2&max_iterations=2` |
| 模型 | `qwen3-max`（阿里云百炼） |
| 搜索 | 博查 API，网络检索开启 |
| 环境 | Python 3.11.15 / commit `e11ea53` 基线代码，未做任何修改 |

选题理由：既是原系统本就擅长的行业研究题（对比公平），又贴近迁移目标的尽调场景。

## 二、V1 的两个致命缺陷

### 缺陷 1：把源文档的占位符当数据写进报告

V1 报告原文：
```
2019年交易规模达 XX万亿元，同比增长 XX%，市场潜力巨大 ##1$$ ##2$$
```

数据源是"原创力文档"上的一份 PPT 模板，其标题本身就写着"汇报人:XXX20XX-XX-XX"。V1 原样搬运了占位符 `XX`，**并挂上两个引用角标**，让编造内容显得有出处。

正则统计：V1 报告含 **2 处 `XX` 占位符、0 处带年份的具体数值断言**；V2 报告 **0 处占位符、6 处具体数值断言**。

> 在尽调场景中这等同于伪造材料——这正是本项目要做反幻觉工程的直接动因。

### 缺陷 2：反思环节空转，迭代白跑

V1 后端日志：
```
Reflect response: { "coverage_analysis": "...关于监管政策变化的具体内容提及较少",
                    "missing_aspects": ["具体的监管政策变化","最新监管趋势"],
                    "is_sufficient": false,
                    "additional_queries": [ { } ] }        ← 生成了空对象
WARNING:root:web_search called with empty query, using context query as fallback
INFO:root:Using fallback query: 供应链金融行业的市场现状、主要风险与监管趋势
INFO:root:Cache hit for query: 供应链金融行业的市场现状...
```

反思**正确识别**出缺少监管政策内容，但生成的补充查询是空对象 → 回退为原始问题 → 命中缓存 → **原地打转**。缺陷不在"不会反思"，而在**反思结果无法转化为有效动作**：单体循环里，产出结构化查询和执行查询是同一个模型的同一轮输出，没有独立环节校验其有效性。

## 三、V2 的进步：Critic 抓住了 V1 栽的那个坑

V2 的 CriticMaster 裁决 `needs_revision`，质量分 5/10，**4 个 critical + 7 个 major**。其中第一条：

> `[critical] hallucination`：引用了来源为"原创力文档"的数据，但该网站是文档分享平台，并非权威行业研究机构。报告未提供具体报告名称、发布机构或链接，无法验证数据真实性和统计口径。这构成严重的"幻觉"问题。

**V2 的审核 Agent 精确识别出了让 V1 栽跟头的同一个信源。** 这是"独立审核环节"价值最直接的证据——不是模型变聪明了，而是架构里多了一个专职质疑的角色。

另两条 critical：报告引用了 `chart_*` 图表但正文中并未渲染；数据时效性存疑（见下）。

## 四、⚠️ 实测发现的三个真实缺陷（迁移时需修复）

### 缺陷 A：Critic 不知道"今天"是哪天 —— 高优先级

Critic 报告了一条 critical：

> "报告引用了尚未发生的未来事件（2025年4月）作为事实依据，这是严重的幻觉和事实错误。"

**这条批评本身是错的。** 实测当天为 2026-08-09，2025 年 4 月是一年多以前。

根因已定位：`agents/critic.py:39` 要求它执行「**时效性**：过时的数据（超过2年）必须标注」，但该文件**从未把当前日期注入提示词**（`datetime.now`/`today` 等 0 处命中，尽管第 16 行 import 了 datetime）。模型只能以训练截止时间充当"今天"。

`agents/writer.py`、`agents/architect.py` 同样 0 处日期注入；只有 `scout.py`(6) 和 `base.py`(2) 有。

> **修复**：在 BaseAgent 统一注入当前日期到 system prompt。成本极低，但直接决定所有时效性判断的正确性——尽调场景里"该企业近两年有无涉诉"是必答项，日期错了结论就全错。

### 缺陷 B：Writer 引用了不存在的图表

Writer 在正文中写了 `chart_*` 占位引用，但对应图表未渲染到报告中。图表由 CodeWizard 以 base64 产出、与正文分属不同事件流，两者缺少一致性校验。

### 缺陷 C：`max_iterations` 语义不一致

请求传 `max_iterations=2`，但 `research_complete` 返回 `iterations: 1`；且 `llm_config.py` 的 `ResearchConfig.max_iterations` 默认值是 1。请求参数与内部配置的优先级需要厘清。

## 五、结论

1. **多智能体的收益是真实的，代价也是真实的**：11 倍耗时换来 18 倍信源、4.4 倍篇幅，以及一个能抓住幻觉的独立审核环节。Stage 5.2 的成本优化因此有明确的靶子。
2. **单体 ReAct 的根本瓶颈不是"不会反思"，而是反思无法可靠转化为动作**——这正是把职责拆给独立 Agent 的理由。
3. **即便 V2，自评也只有 5/10、4 个 critical**。说明"多智能体"本身不等于"可信输出"，必须再叠加清单驱动的核查与强制溯源——这就是 `DESIGN_CORE_MECHANISMS.md` 要解决的问题。
4. 实测暴露的三个缺陷（尤其日期未注入）是迁移期要顺手修掉的技术债。
