## 本轮实现

在现有 Agent 循环中增加轻量问题清单，不新增数据库表、框架或贷款审批路径。

- `plan_investigation`：由 AI 根据用户请求形成最多六个问题、完成条件及是否需要计算。服务端分配稳定 ID，后续不能删除问题、替换任务或降低条件来获得“完成”。
- `address_question`：逐项保存答复、原文引文、计算底稿和限制。区分 `open`（尚未完成）、`answered`（已给出有依据的答复，仍待复核）、`blocked`（资料不足，暂不能完整回答）。代码验证引用及回执，不替代语义判断。
- 量化任务要求实际计算底稿；旧底稿在关联时重新检查授权及原文。引文调序、近重复措辞、状态往返不计新进展。仍保留累计 24 步/420 秒调查预算。
- 收束时仍有开放问题只能明确交付部分结果；报告和前端展示逐问题完成条件、答案、引用、底稿与限制。循环正常结束不再自动表示全部问题已解决。
- Critic 对每个计划问题给出复核回执；“探索性/未经核实”不能免除逻辑审查。所有非空审核引用必须真实连续存在于报告，支持性结论也需要定位，不能拿来源中的数字冒充报告已作出的分析。
- 需要补读或补算的问题回到原 Scout 循环；只纠正解读和措辞的问题交给 Writer。Writer 不能增加/篡改问题、引用、底稿或升级问题状态；修订原子校验并保存历史。历史问题只有完整重新审核通过才销项。
- 报告交付与风险评级继续分开。仍有开放问题则报告受限，确实缺资料则部分报告；没有逐问题复核不能显示质量已通过。未改变企业档案、字段核实、评分和额度规则。

## 当前验收结论与后续顺序

**本阶段功能实现和有界端到端验证已完成，但效果验收未通过。** 没有观察到一次完整有效的“调查—语义复核—补读/补算或修订—重新审核通过”闭环；该路由目前只有离线回归证据，不能宣称线上可靠。520 项回归、正确状态提示和真实引用均不能抵消实际报告错误。

下一步应先留在本阶段收敛效果，不增加业务模块或取消真实性边界：

1. 改善行动选择与工作记忆：把当前可执行动作、已读证据、待补计算展示得更简短明确，减少重复建计划、缓存重读和引用未读来源。允许怎样的有依据计划细化，应与“偷偷降低完成条件”分开设计，不能把模型首轮假设冻结成任务真相。
2. 简化复核输入与引用协议，区分传输/定位失败和内容错误，先确保能持续产生有效审核回执，再评估是否真正检出并修复错误；不要只靠延长超时或继续堆检查项。
3. 用固定材料做多次对照，分别统计工具调用成功率、核心问题回答质量、误报/漏检及最终修复率。小样本中的 5→3 分仅是观察结果，不能证明某一改动的独立因果效果，更不支持宣称整体质量提升。
