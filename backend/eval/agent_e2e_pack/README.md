# 自主调查端到端测试包

全部企业、交易及编号均为虚构。用途是研发验收，不是信用评估或贷款建议。TXT 为 UTF-8，项目知识库入口支持；本包不测试 PDF/OCR。无需下载外部数据，无需创建企业档案或手工填写评分字段。

## 目录及防泄漏

- `uploads/base`：第一次试跑只上传这5个TXT文件。
- `uploads/distractors`：同名不同主体、截止日后事件，用于第二阶段。
- `uploads/supplement`：补件阶段使用，不能提前上传。
- `uploads/security`：单独的文档指令注入测试。
- `uploads/private`：只给另一个账号B上传，绝不放入账号A的库。
- `operator`：查询与步骤，给测试人员看。
- `evaluator`：标准答案、评分模板与检查器，**不得上传或粘贴给调查模型**。

不要把整个测试包拖进知识库，也不要把测试问题中附上标准答案。此数据集是公开开发回归集，不是盲测集。

## 十分钟入门（不含模型与索引等待时间）

1. 打开 http://localhost:5183，用自己的测试账号A登录。当前运行环境此前使用独立库 `industry_assistant_codex`；确认后端没有误切回旧库。
2. 创建全新知识库 `E2E-HX-T01-日期`，上传 `uploads/base` 的5个文件，等待全部解析和索引完成。检查片段正文能显示中文、数字和材料编号，记录文件数及处理状态。
3. 在尽调页选择该库、主体“海岫精密部件有限公司”、自主调查（实验），关闭网络搜索，使用 `operator/TEST_PLAN.md` 的Q1。
4. 如页面提供截止日，填写 `2026-02-20`；若页面没有此控件，应在网络面板确认请求确实带 `as_of`，或用支持该参数的API客户端提交。仅在查询文本中写日期，不能算服务端时点门控测试通过。
5. 保存请求参数、行动列表、调查卡片、最终报告和状态。遇到人工复核暂停，应记录为正常流程分支，不需要为跑通测试而批准贷款。
6. 对照 `evaluator/ORACLE.md` 人工评分，在 `evaluator/result_template.json` 的副本填写结果。没有发生实际检索/阅读的测试项标记 `not_exercised`，不能当作通过。

## 运行原则

每个场景建新库、新研究会话；相同条件比较模式时使用相同材料与模型配置。不要在已开始的研究中途更换知识库。第一轮只跑T01，确认链路后再依次增加复杂度。

记录实际阶段：上传成功 → 解析成功 → 索引成功 → 请求获授权 → 命中 → 原文阅读 → 发现 → 报告或复核暂停。任何阶段失败都先定位，不把“200响应”“报告很长”“有评级”当成成功。

本包期望模型承担追查与分析，但不要求机械复现唯一工具顺序或唯一文案。字段仍未核实、额度未给出不代表失败；虚构企业资料不应被升格为真实权威数据。

## 静态检查

在仓库根目录运行：

```powershell
python backend/eval/agent_e2e_pack/evaluator/validate_pack.py
```

该脚本只验证材料完整性、关键数字和评分模板结构，不调用模型、不连接数据库、不声称E2E已通过。
