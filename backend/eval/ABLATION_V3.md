# Critic v3 消融实验报告（2026-08-11）

## 实验问题

本轮不只比较“哪个数字更高”，而是分别回答：

1. 确定性扫描器是否提供独立增益；
2. 结构化核查清单是否提供模型无法从正文恢复的信息；
3. 换弱模型后，架构能否维持可用的检出与误报平衡；
4. 结论能否在未参与调优的 case-level 留出集复现。

## 固定配置与审计口径

- A：`deepseek-v4-flash`，完整架构
- B：`deepseek-v4-flash`，关闭扫描器
- C：`deepseek-v4-flash`，同时关闭清单与扫描器
- D：`deepseek-v3.2`，完整架构（弱模型对照）
- 全部温度 `0`、每例重复 `3` 次、并发 `5`
- 开发集：28 例，SHA256
  `ffd692dd5740338a206c6c0d5a80b64006b0c03c850d3b297aa3fbe3246a438f`
- 留出集：14 例，SHA256
  `26842bd9ef385c7b86d19b6fd6536df772b50ea2863a6e162b1f7b355eec3a73`
- 任何 LLM 调用失败都不进入算法指标分母，并使实验命令失败。本轮八组完整实验
  均为 `LLM失败=0`。
- 对照误报定义为产生任何 `critical/major` 问题，不限 issue 类型。

指标分成两层：

- **目标命中**：是否命中预先指定的违规类型或等价描述，测分类与归因是否正确；
- **坏报告拦截**：最终 `verdict != pass`，测生产链路是否阻止坏报告通过。

二者不可互相替代。模型可能以 `hallucination` 而非
`conflict_silently_resolved` 打回同一句话，此时拦截成功但目标命中失败。

### 留出集揭示的缺陷

A 组反而弱于 B 组，不是“扫描器总体有害”的充分证据，而是一个可定位的
确定性误报：HCLN-02 已明确写出实缴资本存在“两种互不相容的记载”，并拒绝
依据任一口径评价资本实力；扫描器因词表不认识“互不相容”，稳定 3/3 将其判为
`conflict_silently_resolved`。与此同时，HINJ-02 用“实际到位资本”改写“实缴资本”，
扫描器又因别名缺失而漏掉。见 `BADCASES.md` BC-26。

该问题已按语义类别修复并锁回归：补足到位资本别名以及互不相容、不同口径、
不同记载三类分歧披露表达。修后确定性测试为显式违规 7/7、开发集对照 0/18，
新增正反边界断言全部通过。

**留出集已经用于定位并修复 BC-26，因此从此退役为回归集。** 不重跑它并把新数字
称作“留出泛化结果”；下一次封板必须另建未被本轮观察或调优的新盲测集。

## 能成立的结论

1. **结构化清单是最大且可复现的准确率来源。** 关清单后目标命中由开发集
   100% 降至 40%，留出集由 83.3% 降至 38.9%。这支持“清单提供不可从正文
   恢复的核查状态”，而不是仅优化提示词格式。
2. **扫描器有工程价值，但尚不能宣称稳定提高总体准确率。** 开发集 A 比 B
   多命中 1/30 且误报略低；首次留出集却暴露词法边界缺陷。确定性、零 token、
   LLM 失败时仍能门控是已被测试证明的属性；泛化增益仍需新盲测集验证。
3. **弱模型不是可用替代。** D 组虽然几乎总能拦截坏报告，但开发集误报 98.1%、
   留出集误报 100%，本质是“见谁都拦”，不能称为安全性更强。
4. **只报拦截率会掩盖分类退化。** C 组坏报告拦截仍是 100%，但目标命中只有
   40%/38.9%；模型常因泛化理由拒绝报告，却没有稳定识别被测失效。
